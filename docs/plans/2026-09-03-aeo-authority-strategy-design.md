# AEO 權威/可信度信號戰略設計文件

- **日期**：2026-09-03
- **範圍**：lin.hsiehting.com 作者身分的「權威/可信度信號」（E-E-A-T for AI），不含技術 AEO 基礎建設重建
- **觸發**：參考 [IDAEO](https://idaeo.ai/)（Identity Data AEO）的方法論——把品牌資料轉成 AI 可信賴引用的「有出處鏈（provenance）資產」——轉譯到個人醫療部落格情境
- **資源限制**：僅本人瑣碎時間，不含外部公關/媒體/學會發表類投入

## 1. 目標與定位

IDAEO 幫「品牌」做的事，是把散落的資料整理成有出處鏈的結構化資產，讓 AI 敢引用。
對一位個人醫師而言，「品牌」就是**林協霆這個人的專業身分**——AI 判斷「這篇文章的作者是誰、
夠不夠格說這句話、是否被其他可信來源認證」，靠的不是文章寫得多好，而是**作者身分本身的
實體（entity）在多少獨立、可信的知識圖譜節點上被交叉驗證**。

本文件聚焦單一痛點：**如何提升權威/可信度信號**，不重做站內 AEO 技術基礎建設
（FAQ schema、JSON-LD、llms.txt、Zenodo DOI 已相當完整，見第 2 節）。

## 2. 現況盤點——身分驗證錨點

依「可被交叉驗證的程度」拆成三層：

| 層級 | 現況 | 缺口 |
|---|---|---|
| **自站聲明**（self-asserted） | `Physician` JSON-LD 全站注入、`/about`、`/cv`、每篇 `MedicalReview` 標註審稿人＋資格＋日期 | 已足夠，不用再加 |
| **獨立第三方登記**（third-party verified identity） | ORCID、Google Scholar 已接、`sameAs` 有串 | **無 Wikidata 實體**（Google 知識圖譜/多數 LLM 實體消歧首選來源）；`socials.linkedin`/`twitter` 留空，`sameAs` 陣列偏薄 |
| **機構背書**（institutional cross-reference） | 站上單向連到和信官網 | **和信官網沒有反向連結**回本站；查無醫院醫師介紹頁是否列出個人網站/ORCID |

**額外發現的低垂果實**：

- Zenodo DOI（105/110 篇已 mint）本身是強權威訊號，但**未設定 ORCID ↔ Zenodo 自動同步**——
  一次性設定即可讓每篇新 DOI 自動掛進 ORCID works 列表。
- Google Scholar 的「被引用」需要他人真的引用，短期無法自己推動，不列入行動項。
- `/cv` 有 PDF，但**沒有對應的機器可讀 `EducationalOccupationalCredential` schema**，
  AI 目前只能吃 `Physician` JSON-LD 裡的文字欄位驗證資歷。

## 3. 分層行動計畫

依「一次性設定 vs. 需要持續投入」與成本交叉分層，全部設計成**可併入現有發文流程**，
不額外開會、不對外公關。

### Tier 0 — 一次性設定，做完就不用再管（優先）

1. **建立 Wikidata 實體條目**：登記姓名、職稱、機構、ORCID、專科別。一次建好，
   `sameAs` 補上連結即可。
2. **ORCID ↔ Zenodo 自動同步**：ORCID 設定「Auto-update」信任 Zenodo，之後新 DOI
   自動掛進 works，不用手動維護。
3. **`sameAs` 補齊**：把 Wikidata 連結加入 `src/config.ts`；`socials.linkedin`
   若已有帳號一併補（沒有就不用為填欄位新辦）。
4. **向和信索取一個反向連結**：請院方公關/資訊室在院內醫師介紹頁加一行
   「個人臨床筆記」連到本站——零技術成本，換來機構級背書。

### Tier 1 — 併入現有寫作流程，邊際成本趨近於零

5. **CV 頁補 `EducationalOccupationalCredential` JSON-LD**：資料已有（學經歷、
   專科證書），只是多一個 schema 區塊。
6. **參考文獻優先挑「近 2 年、已被高引用」的論文**：同樣是寫引用，選擇會讓 AI
   認為本站站在文獻前緣的來源，不多花時間。

### Tier 2 — 需要持續但輕量的動作（可選，先擱置）

7. 定期（如每季）自我搜尋是否有第三方在轉述本站內容，適時附上原文連結澄清。
   非本輪重點，列入文件供未來參考。

## 4. 風險與非目標

**風險與紅線**：

- Wikidata 條目若寫得像自我宣傳會被社群標記刪除——內容需嚴格中立、僅陳述可查證
  事實（職稱、機構、學位），不寫評價性字句，符合站上醫療法 §87 紅線精神。
- 向和信索取反向連結是「請求」不是「要求」，院方流程慢或拒絕不影響其他 Tier 0
  項目，不要因此卡住整體進度。

**非目標（本輪不做）**：

- 不重做技術 SEO/AEO 基礎設施（FAQ schema、JSON-LD、llms.txt 已足夠）
- 不建立量測儀表板追蹤「AI 是否真的引用我」——留在 Tier 2 之後，若想做可另開一輪規劃
- 不評估付費採用 IDAEO 平台本身
- 不做外部公關/媒體/學會發表（超出資源限制）

## 5. 驗收方式（輕量，非儀表板）

- Tier 0 四項全部完成 = 這輪目標達成的最低標準
- 之後每次 `pnpm run audit:all` 順手檢查 `sameAs` 陣列是否仍完整
  （Wikidata/ORCID/Scholar 連結沒有失效）
- 3–6 個月後手動搜尋一次「林協霆 腫瘤」在 Google 是否出現知識圖譜卡片，
  作為 Wikidata 生效的非正式訊號
